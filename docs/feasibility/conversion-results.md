# PDF conversion feasibility

The current converter produces drafts only, always requiring visual review. Original PDFs are retained. It uses pdfplumber 0.11.10 for positioned text and pypdfium2 5.15.2 for rasterization. Selected pages are bounded; detected chord rows are matched against character positions, and apparent tab groups retain literal extracted characters. Automatic completeness cannot be inferred from image counts.

A preliminary pass of the private sample generated drafts for p1–p4. In p3, a page with no embedded images contains substantial visible lyrics and tab but yielded only 75 draft characters. It is unsupported for automatic conversion and requires the original page and manual transcription or a separately authorized provider. p2 contains two columns and requires detailed ordering and anchor review; p1 has tab and spans two pages; p4 is a multi-song book and requires separate regions. Line-level omissions, extra lines, chord-anchor errors, tab loss and correction times have **not** yet been measured. No draft is accepted on the basis of this pass. A pdftotext comparison is not ground truth for these sources. Graphical notation and extraction ambiguity remain unresolved; use the original as fallback.

A preliminary automated comparison of p1 against its paired ChordPro source found 29 of 33 normalized lyric-line instances in the draft, with 26 draft lines not matched to a source lyric line (these include headings and annotations). Eighteen of 33 source chorded line instances had an identical lyric and chord-offset tuple somewhere in the draft. This is a conservative diagnostic, not a measured count of wrong chords: wrapping, repeated lines and non-lyric annotations affect it. It does not replace page-by-page review, and the correction time remains unmeasured.

A rendered p2 draft was inspected against the original page. The initial output interleaved columns and treated several words as chords; this is a known failing case, not a usable conversion. Column heuristics have since changed, but the resulting fidelity remains unverified. For p3, the 75-character draft omits almost all visible music. For p4, page selection includes two separate songs and must be split into regions before import. The manual fallback is to retain the original and enter or correct the ChordPro in review; no automatic acceptance is provided by this milestone.

A timed visual triage pass compared the selected originals and draft renders: p1 approximately 0.28 minutes (two source pages), p2 0.18 minutes (two source pages), p3 0.10 minutes (one source page), and p4 0.12 minutes (two source pages). This timing measures only a quick rejection/triage pass, not correction or full verification. p1 visibly merges a tab line and treats some chord rows as lyrics; p2 interleaves columns and misclassifies words; p3 omits nearly the entire page; p4 combines songs and fails to retain the intended inline-chord presentation. All four drafts remain unaccepted. Exact missing/extra line and wrong-anchor totals, and the time to repair each draft, were not measured.
