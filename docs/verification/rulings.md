# Recorded implementation rulings

This report carries every ledger ruling and its stated cost. Earlier entries are historical where later implementation completed the work; the limitations described below remain open. No private corpus content is included.

## M1 feasibility

- Task 3: Ruling: page-by-page correction timing and detailed ground-truth counts are deferred to task 5, where the full rendering pipeline is inspected; drafts remain review-only and the known failed vector and column cases retain original references — cost if wrong: feasibility decisions could rely on incomplete fidelity evidence, so milestone exit remains gated on that review.
- Task 5: Ruling: use the measured lexer, extraction adapters and Chromium renderer for M2 while keeping PDF drafts review-only; detailed per-page error counts and correction times remain unverified because none of the failed drafts was repaired or accepted — cost if wrong: automation quality and review workload may be worse than the sample suggests; originals and manual review remain mandatory.

## M2 online

- Task 2: Ruling: The initial shell links to later feature placeholders, and the auth browser test fetches the retained synthetic original through the browser rather than displaying it in a review pane — those panes belong to tasks 3–7 and will be exercised there; cost if wrong: the current shell alone does not provide a usable library workflow.
- Task 2: Ruling: The worker heartbeat currently makes readiness unavailable when a worker is required; worker heartbeat implementation belongs to task 3 — cost if wrong: readiness will remain unavailable for worker-dependent configurations until that task is finished.
- Task 3: Ruling: AI conversion accepts at most five full pages and rejects crop selections; local extraction accepts normalized crops and records their coordinates in draft provenance — the adapter does not yet send cropped regions and originals remain available — cost if wrong: a user must submit a larger page area than desired or use local conversion; explicit provider authorization remains mandatory.
- Task 3: Ruling: Similar-title suggestions inspect at most 5,000 arrangements and never merge automatically — this bounds review work and avoids unintended matches — cost if wrong: a very large library may omit a relevant suggestion.
- Task 3: Ruling: Extracted crop provenance is retained with the import draft rather than materializing a separate crop asset on acceptance; the complete original and page references remain available — cost if wrong: downstream exports must include draft provenance or recreate the crop to reproduce the selected region.
- Task 4: Ruling: Search accepts up to 25 literal terms, intersects matches across source text and tags, and treats tag terms as case-folded substrings; this bounds FTS work and makes mixed title/tag queries useful — cost if wrong: exceptionally long queries are rejected and a tag may match a substring the user did not intend.
- Task 5: Ruling: Auto columns use the measured available music width, a 300px minimum column width and the selected font size; extra-wide tab uses horizontal scrolling rather than changing that minimum — cost if wrong: some unusually wide chord or lyric content may need a manually reduced column count, although requested font size is never reduced.
- Task 5: Ruling: The private real-arrangement check records DOM overflow and screenshots but the screenshots were not visually inspected; the sample had no tab — cost if wrong: glyph-level overlap or clipping may remain undetected and real-tab fidelity remains unverified.
- Task 6: Ruling: Nested source transpose directives use a stack: a valueless directive restores the preceding value; this matches the ChordPro directive documentation and an independent synthetic CLI check — cost if wrong: unusual source scopes could display the wrong transposition, so unknown forms remain warnings and unsafe variant serialization is refused.
- Task 6: Ruling: Saved transposed variants are refused when scoped transpose directives or custom chord definitions cannot be serialized safely; users may edit a new arrangement manually — cost if wrong: some valid variants need additional manual work rather than one-click saving.
- Task 6: Ruling: Chord diagrams use a small pitch-validated authored GCEA dictionary and only four-fret-list custom definitions without base-fret notation; other shapes are explicitly unknown — cost if wrong: valid chords or shapes may lack a diagram until the dictionary and definition parser are extended.
- Task 7: Ruling: The PDF renderer splits recognized complete tab groups across pages and rejects an indivisible tab block taller than the available page — cost if wrong: valid but unrecognized tab group layouts may require manual restructuring before export; it will not silently produce a partial artifact.
- Task 7: Ruling: Real-PDF visual page inspection remains unverified; automated text-instance, page-size, font-embedding and local raster generation checks are recorded, and M3 will proceed under this explicit limitation — cost if wrong: visual overlap or clipping may escape the automated checks.

## M3 offline and portability

- Pre-flight: Ruling: M2 used migration number 006 for PDF jobs, so assign setlists migration 007 and reserve subsequent numbers uniquely — cost if wrong: later migrations expecting the planned number must be updated.
- Pre-flight: Ruling: M2 stores preference envelope timestamps as seconds in `updated_at`; M3 reconciliation will convert those values exactly to integer milliseconds at its boundary and preserve the existing wire schema until a compatible migration is verified — cost if wrong: timestamp precision or tie-breaking could differ for old clients.
- Pre-flight: Ruling: Proceed with M3 while retaining the explicitly unverified real-PDF visual inspection and physical-phone checks in the milestone report; automated extracted-text, dimensions, font and raster generation checks passed — cost if wrong: visual clipping or device-specific layout failures could remain undetected.
- Task 2: Ruling: On browsers without Web Locks, removing an individual selection retains unreferenced shared asset bytes until the user chooses removal at sign-out; this avoids deleting bytes another tab could be publishing without cross-tab coordination — cost if wrong: browser storage may retain private originals longer than expected and consume extra space, so the UI/docs must disclose it and explicit sign-out removal must delete them.
- Task 2: Ruling: Where Web Locks are unavailable, coordinate shared-cache publication and sign-out cleanup using a renewable two-minute IndexedDB lease, with a 30-second acquisition timeout; leave unreferenced individual-selection assets until explicit sign-out as recorded above — cost if wrong: a tab suspended beyond the lease or an abnormal clock jump could let concurrent cleanup race a resumed operation, or a crashed tab could temporarily delay downloads.
- Task 3: Ruling: Downloaded setlists now require a hash of the ordered setlist payload before partial offline playback; sets downloaded by task 2 before this hash was introduced report incomplete and require re-download — this prevents a corrupted setlist from silently changing occurrence order — cost if wrong: a previously complete offline set must be downloaded again, and its cached copy is not offered as a partial set until refreshed.
- Task 3: Ruling: Migration 009 records setlist deletion tombstones from this point forward; unknown IDs and sets deleted before migration remain unavailable because historical hard deletions have no reliable tombstone — cost if wrong: an old cached deleted set may be shown as unavailable rather than definitively deleted until the user removes it.
- Task 3: Ruling: Run WebKit reconnect checks with isolated persistent Playwright profiles: in this harness a standalone WebKit ephemeral context lost a synthetic Cache Storage entry on ordinary online navigation, while a persistent profile retained it. This matches the intended retained-browser-storage scenario; the ephemeral-context behavior remains unverified for private-browsing use — cost if wrong: offline behavior in transient/private contexts may differ from the reported persistent-profile results.
- Task 4: Ruling: Operational settings and provider credentials live in the operator environment, outside the managed library; backups will preserve database authentication but require those external values to be reprovisioned instead of importing machine-specific source roots — cost if wrong: a restored instance needs additional manual configuration, and lost external secrets cannot be recovered from the archive.
- Task 4: Ruling: Require a destination path that does not yet exist, including rejecting an already empty directory, so restore can publish one validated directory without merging or touching preexisting paths — cost if wrong: operators must choose a new path and cannot pass an already-created empty mount directory directly.
- Task 4: Ruling: Snapshot file locking plus a SQLite write reservation quiesces managed files and all database writers without imposing a new lock protocol on every API or worker connection; in-flight jobs are captured as failed for manual review and derived PDFs are regenerated — cost if wrong: long snapshots can temporarily delay writers or hit their SQLite timeout, and a writer that creates a new managed file without the existing file lock could escape the consistency boundary.
- Task 4: Ruling: Portable arrangement bundles carry a filtered JSON catalog and related files but do not act as complete library restore archives; only complete library exports/backups restore — cost if wrong: importing a single bundle requires manual handling until a dedicated importer exists.
- Task 5: Ruling: Keep the application server bound to loopback inside the API container and use a local TCP relay exposed only through the host loopback port; Docker-network peers can still reach that relay, so the network is restricted to trusted local containers — cost if wrong: an untrusted container joined to that network could reach the authenticated local API, and this setup must not be treated as remote-deployment security.
- Task 5: Ruling: Use npm workspace test scripts via `npm test --workspaces --if-present` because the root package defines no test script; this runs both web and music tests — cost if wrong: a future root-only test would need a separate command.
- Task 5: Ruling: Base image tags and Debian runtime packages are versioned by the Docker build at build time rather than pinned to immutable digests or a Debian snapshot; Python and npm packages use lockfiles and Playwright pins Chromium — cost if wrong: base or OS package updates can make later builds differ or fail; the built image and local verification remain reproducible only within those constraints.

## Review of remaining effects

The M2 placeholder shell and missing worker heartbeat were intermediate conditions; subsequent tasks implemented those workflows and heartbeat. PDF drafts still require review; measured correction times and detailed per-page fidelity are unavailable. Live provider fidelity, physical-phone behavior, transient/private WebKit storage, and visual inspection of real-song raster pages remain unverified. The compact diagram dictionary, export restrictions, offline storage/lease behavior, old setlist tombstone limits, source crop provenance, and search bounds remain product limitations as stated above. The local container bind is not a remote deployment security design.
