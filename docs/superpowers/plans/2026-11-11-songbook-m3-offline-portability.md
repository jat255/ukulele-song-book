# Setlists, Offline and Portability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, inline. Steps use checkbox (`- [ ]`) syntax for tracking. No delegation is authorized by this plan.

**Goal:** Add ordered setlists, reliable downloaded playing, preference reconciliation, setlist PDFs and verified portable export/backup/restore.

**Architecture:** Reuse M2's canonical snapshots, revision checks, performance transforms and PDF jobs. Explicit authenticated downloads place versioned snapshots/assets in browser storage with verified completeness; reconnection refreshes server content without permitting offline source edits. Versioned archives preserve portable song content and app metadata, while local container packaging makes the application reproducible without deploying it.

**Tech Stack:** M2's locked stack, browser IndexedDB/Cache Storage/service workers, web app manifest, Playwright Chromium/WebKit, Python archive/hash/SQLite backup APIs, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-10-ukulele-songbook-design.md`; [master plan and contracts](2026-11-11-ukulele-songbook.md); prerequisite [M2](2026-11-11-songbook-m2-online.md).

## Global Constraints

All master-plan constraints/types apply. “Offline use begins after a successful authenticated download; it is not an offline first-login promise.” “Browser storage can be evicted, so offline status must be verified from actual cached assets.” “Cached content can remain available until explicitly removed, with a clear stale/deleted indicator.” “In setlist exports, default to a new song starting on a new page; optionally pack songs onto shared pages to minimize paper use.” Canonical editing/import/server PDFs remain online. No deployment, publication or infrastructure changes.

## Review Focus

1. Same arrangement appears twice in a set: preserve both ordered occurrences through play, downloads and PDF export (task 1).
2. Download interruption or partial cache eviction: do not label unavailable assets as downloaded (task 2).
3. Server edit/deletion while offline: keep a playable stale copy with truthful status and explicit refresh/removal (task 3).
4. Concurrent preference changes and stale canonical editing: reconcile local settings deterministically while preserving source revision conflicts (task 3).
5. Corrupt or unsafe archive/failed restore: leave existing content untouched and never extract outside the destination (task 4).

**Interfaces:** Authenticated `GET /api/downloads/arrangements/{id}` and `/setlists/{id}` return `DownloadManifest` with library ID, schema version, exact revisions, unique snapshot/assets, SHA-256/size/MIME and optional-original entries. `downloadSelection(manifest: DownloadManifest, includeOriginals: boolean): Promise<DownloadResult>` stores only selected snapshots/assets. `verifyAvailability(selectionId: string): Promise<Availability>` inspects actual local records/assets; states are `online-only`, `downloading`, `downloaded`, `incomplete`, with independent `outdated`/`deleted` flags added in task 3. `removeDownload(selectionId: string): Promise<void>` reference-counts shared assets. Client storage is scoped by library and authenticated principal; it never includes provider credentials/session tokens.

- [ ] **Step 1 — Write offline failure tests.** Download a set sharing songs/assets and assert originals are excluded by default. Interrupt halfway, simulate quota failure, delete an actual asset and simulate service-worker update; `verifyAvailability` must report incomplete rather than downloaded. Verify optional PDF originals by hash before showing available. Download while authenticated, disable network, cold reload, open/transpose downloaded songs, display diagrams and scroll with no runtime asset requests. An online-only song is explicitly unavailable. Canonical edit/import/server PDF actions show a connection requirement and never enqueue source mutations. Logout offers removal of private downloads, with deletion selected by default; choosing retention clearly leaves a local private copy.
- [ ] **Step 2 — Run failing tests.** `npm test --workspace @songbook/web -- downloads`, `uv run pytest tests/integration/test_download_manifest.py -q`, and `npm exec playwright test tests/e2e/offline-downloads.spec.ts`.
- [ ] **Step 3 — Implement manifests and transactional completeness.** Download immutable snapshots, diagrams, bundled fonts/rendering code and required crop assets; source PDF is optional. Deduplicate shared files. Stage verified assets and publish a completed IndexedDB manifest only when all required hashes match. Cache Storage and IndexedDB do not share a transaction, so record staging intent, reconcile on startup and verify real assets before returning downloaded. Keep the previous complete revision if a refresh fails. Request persistent storage where supported and expose estimated usage, errors, remove/re-download controls; never equate permission granted with content present.
- [ ] **Step 4 — Implement installable shell and local reader.** Cache only versioned shell assets after an online visit; use explicit manifests for private music, not indiscriminate authenticated-response caching. Offline navigation loads the shell then local snapshots and the same music package. Bundle all required fonts/icons/chord rendering; no remote CDN dependencies. An update cannot claim an older schema is readable if migration fails: retain the old complete cache or report re-download required. ## Task 3: Reconnection, stale/deleted states and preference reconciliation

**Files:** Create `apps/web/src/offline/{sync,preferences}.ts`, `apps/web/src/offline/sync.test.ts`, `server/songbook/api/sync.py`, `tests/integration/test_sync.py`, `tests/e2e/offline-sync.spec.ts`, `docs/verification/offline.md`; modify preferences API, download/status UI and canonical editor connection checks.

**Interfaces:** `POST /api/sync/check` accepts known arrangement IDs/revisions and setlist revisions; returns current/deleted/unavailable states without deleting local copies. `refreshDownloads(ids: string[]): Promise<RefreshReport>` stages new revisions through task 2. `PreferenceEnvelope<T> = {schemaVersion:1; value:T; updatedAtMs:number; deviceId:string}` per independent play/performance/print preference group. `mergePreferenceGroup<T>(local: PreferenceEnvelope<T>, remote: PreferenceEnvelope<T>): PreferenceEnvelope<T>` selects the lexicographically greater `(updatedAtMs,deviceId)` tuple. Persist a monotonically increasing local timestamp `max(Date.now(), previous+1)`; the personal-app latest-write policy is based on device timestamps, not a claim of global clock accuracy.

- [ ] **Step 1 — Write sync tests.** Download revision A, disconnect, edit to B on server, reconnect: mark A outdated, retain its playable copy until successful refresh, then use B. Server deletion marks cached copy deleted while keeping it playable until removal; 401/network errors mark sync unavailable, never imply deletion. A setlist with one missing item stays ordered and indicates partial availability. Conflicting offline preference updates converge on the same tuple winner in both sync directions, including equal timestamps and duplicate retries. Source edits keep M2's 409 handling and no offline source-write queue; preference sync never changes canonical hashes.
- [ ] **Step 2 — Run failing tests.** `npm test --workspace @songbook/web -- sync`, `uv run pytest tests/integration/test_sync.py -q`, and `npm exec playwright test tests/e2e/offline-sync.spec.ts`.
- [ ] **Step 3 — Implement bounded reconnection.** Check revisions when authenticated connectivity returns; report stale/deleted/unavailable distinctly and refresh explicitly downloaded selections using verified staging. Preserve old complete snapshots if interrupted or unauthorized. Keep local performance settings usable offline, persist per-group envelopes and merge deterministically with the server using resource ETags/retry for metadata conflicts only. Source content is never a latest-write-wins resource. Handle changed set membership visibly and download new members only as part of refreshing that downloaded set.
- [ ] **Step 4 — Exercise target browsers.** Run automated cold-start/offline/reconnect tests in Chromium and WebKit. Also verify laptop and actual phone browser airplane-mode cold reload, tab alignment, diagrams, transpose, manual/auto-scroll, app-shell update, original-PDF choice, eviction/incomplete-state recovery and logout removal. Record device/browser versions and outcomes; absent physical-device access is reported as unverified rather than silently substituted by a 390px viewport test. Document the device-clock limitation of preference reconciliation.
- [ ] **Step 5 — Verify and commit.** Run offline/sync suites and canonical conflict regressions, typecheck/build and Ruff. Expected: coherent downloaded/outdated/deleted states and preserved canonical content; no stale copy is misrepresented as current. Commit `feat: reconcile offline downloads and performance preferences` and update verification/progress documents with any real-device limitation.

## Task 4: Portable library export, consistent backup and clean restore

**Files:** Create `server/songbook/portability/{manifest,export,backup,restore}.py`, `server/songbook/api/exports.py`, `tests/integration/test_portability.py`, `tests/integration/test_restore.py`, `docs/{portability,backup-restore}.md`, `tests/fixtures/synthetic/portable-library/`; modify CLI, library export UI and generated API types.

**Interfaces:** `export_arrangement(id: str, destination: Path, include_sources: bool) -> ExportManifest`; `export_library(destination: Path) -> ExportManifest`; versioned `ExportManifest` records stable IDs, relative paths/hashes, song/arrangement relationships, provenance/page refs, tags/favorites/practice notes, preferences, setlists and revision history. It excludes credentials, sessions and machine-specific input-root paths. `backup_library(destination: Path) -> BackupManifest` creates a consistent private snapshot of canonical files, originals/crops/revisions, runtime configuration and SQLite state. `restore_archive(archive: Path, destination: Path, mode: Literal['portable','backup']) -> RestoreReport` requires a new empty staging destination and publishes it only after validation; no implicit merge into an existing library.

- [ ] **Step 1 — Write archive/restore assertions.** Build a synthetic library with variants, shared book pages, tab/unknown directives, accepted revisions, favorite/tag/note metadata, preferences and duplicate set occurrences. Export and restore into an empty instance; assert exact canonical/original/revision hashes, stable IDs, relationships and metadata, then rebuild search from files and render a restored song. Test a pending write/live job at backup time: backup quiesces writers and captures consistent state; restore does not restart previously submitted paid work. Reject bad hashes, unsupported manifest versions, path traversal, symlinks, excessive expansion and truncated archives without altering an existing library. Portable export contains no auth/provider secrets or local absolute source paths.
- [ ] **Step 2 — Run failing tests.** `uv run pytest tests/integration/test_portability.py tests/integration/test_restore.py -q`.
- [ ] **Step 3 — Implement portable archives and authenticated downloads.** Export standalone ChordPro with required inline definitions; retain unknown source content. Full portable export includes versioned JSON metadata and deduplicated source/assets/history using relative paths and checksums. Arrangement export offers a plain `.chordpro` and an optional archive with its related metadata/source material. Stream large archives through bounded background jobs rather than loading the collection into memory. Keep exports private and omit lyrics/secret-bearing paths from routine logs.
- [ ] **Step 4 — Implement consistent operational backup/restore.** Add CLI commands `uv run songbook export --output <archive>`, `backup --output <archive>`, `restore --archive <archive> --destination <empty-path> --mode portable|backup`, and `reindex`. Acquire a maintenance lock honored by API/worker writers, recover pending intents, drain active local writes, create a SQLite backup and matching file/config snapshot, then release the lock. Backup may contain private auth/provider configuration and is never committed or served as a public static asset; document local protection and operator-controlled destination. Portable export excludes these secrets. Restore validates in staging, migrates/reindexes as needed, resets sessions and expired leases, and leaves ambiguous AI jobs review-required. Report any external credential/config prerequisites explicitly. Do not import machine paths as automatically trusted source roots.
- [ ] **Step 5 — Verify clean restore and commit.** Run archive suites plus storage recovery tests. Restore an ignored backup into a separate empty local instance, verify login/reprovisioning behavior, open originals, compare metadata/setlist order, search and generate a complete PDF. Reopen restored standalone ChordPro independently. Record exact restore commands and measured results without secrets/private lyrics. Commit `feat: add portable export and verified backup restore`.

## Milestone exit

Ordered sets play/export consistently; downloaded songs cold-open and transpose offline; changed/deleted/incomplete states are truthful; source conflicts preserve edits. Portable export and operational backup restore into a clean instance with files and metadata verified. Local packaging and documentation are reviewable. The repository is ready for a separate private-deployment plan, subject to explicitly recorded unverified environment/provider checks.
