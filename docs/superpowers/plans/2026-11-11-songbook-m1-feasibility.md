# Conversion and Portability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, inline. Steps use checkbox (`- [ ]`) syntax for tracking. No delegation is authorized by this plan.

**Goal:** Establish a repeatable conversion corpus and measured parser, conversion and PDF-rendering decisions before building the application around them.

**Architecture:** Exercise adapters using selected private originals and authored synthetic fixtures. Preserve original source bytes separately from a derived music model. Reuse the resulting music package and PDF renderer in the application, while keeping all private evidence ignored.

**Tech Stack:** npm workspaces, TypeScript, Vitest, Python/uv, pytest, Ruff; candidate ChordSheetJS, pdfplumber and pypdfium2 adapters; React/Vite and Playwright Chromium for layout; pypdf for PDF inspection; independent ChordPro CLI.

**Spec:** `docs/superpowers/specs/2026-11-10-ukulele-songbook-design.md`; read alongside [the master plan](2026-11-11-ukulele-songbook.md).

## Global Constraints

All master-plan constraints and shared types apply. “Preserve unsupported directives and original source text on round trips.” “Provider credentials remain on the server.” “Tablature transposition is deferred.” Never write to the source collection or commit private songs/evidence. Live provider calls require configured access and explicit authorization for the selected pages; no collection-wide paid job.

## Review Focus

1. Unknown directives, CRLF and Unicode: unchanged export must preserve bytes (task 2).
2. Chord-only extraction from vector-heavy lyrics: flag missing content despite zero embedded images (task 3).
3. Two columns sharing similar vertical positions: read all of column one before column two (task 3).
4. Literal chords/directives inside tab: preserve the string grid, including spaces and braces (task 2).
5. A long section or wide tab defeats a one-page layout: retain all content at the selected text size and report infeasible settings (task 5).

## Task 2: Source-preserving ChordPro parser boundary

**Files:** Create `packages/music/{package.json,tsconfig.json}`, `packages/music/src/{model,source,parser,cli}.ts`, `packages/music/test/{source,parser}.test.ts`, `tests/fixtures/synthetic/{directives,mixed-tab,unicode}.chordpro`, `server/songbook/music_bridge.py`, `tests/unit/test_music_bridge.py`, `docs/feasibility/chordpro-support.md`.

**Interfaces:** Define the master plan's concrete `MusicDocument`, block union and chord definition types here, including ordered `DirectiveBlock` entries for scoped key/capo/transpose. Export `parseSource(source: string): MusicDocument`, `applySourceEdits(source: string, edits: {span: SourceSpan; text: string}[]): string`, and `exportSource(document: MusicDocument): string`. Blocks retain source offsets; metadata is multi-valued, not flattened. CLI: `node packages/music/dist/cli.js` consumes one JSON request `{op:'parse',source:string}` per process and emits `{document:MusicDocument}` or structured error. Python `parse_source(source: str) -> dict` validates the result and enforces subprocess timeout/output limits without a shell.

- [ ] **Step 1 — Write exact preservation and semantics tests.** Include these assertions in `source.test.ts`/`parser.test.ts` (authored content only):

  ```ts
  expect(exportSource(parseSource(rawWithCRLFAndUnknownDirective))).toBe(rawWithCRLFAndUnknownDirective);
  expect(parseSource('[C]Lan[D/F#]tern').blocks[0]).toMatchObject({
    kind: 'lyric', segments: [{chord: 'C', lyric: 'Lan'}, {chord: 'D/F#', lyric: 'tern'}]
  });
  expect(parseSource('{start_of_tab}\nA|--[C]--  |\n{key: Z}\n{end_of_tab}')
    .blocks[0]).toMatchObject({kind: 'tab', text: 'A|--[C]--  |\n{key: Z}\n'});
  ```

  Add named cases for aliases (`sov/eov/soc/eoc/sot/eot`), `label="…"`, custom `define` with four/six strings, comments, empty lyric segments/adjacent chords, chord-only lines, non-BMP Unicode before an edit span, unsupported constructs, unmatched section/tab, scoped `{key}`/`{capo}` and `{transpose}` including reset. Unsupported semantics must produce diagnostics while retaining source; never silently render a false interpretation. Python tests assert malformed/oversized/timeout CLI output becomes a controlled error, not accepted music.
- [ ] **Step 2 — Run failing tests.** `npm test --workspace @songbook/music -- source parser` and `uv run pytest tests/unit/test_music_bridge.py -q`; verify failures concern the missing boundary behavior.
- [ ] **Step 3 — Implement adapter and minimal semantics.** Evaluate ChordSheetJS against the fixtures; preserve raw source independently with a span-based lexer so parser normalization cannot destroy unknown content. Decode known aliases, section labels, metadata, chord anchors and tab blocks into the derivative model. Recognized unimplemented directives remain literal/flagged. Apply source edits from highest offset downward; reject overlapping/out-of-range edits. Neither parsing nor export executes embedded markup, images, filesystem includes or directives. Keep scoped musical metadata in ordered blocks so later transforms do not treat all keys as one global key.
- [ ] **Step 4 — Exercise real originals and independent renderer.** Parse the three selected ChordPro samples, assert byte-identical unchanged exports, compare section/tab/custom-definition counts, and render exported files with the installed ChordPro CLI using its documented ukulele configuration. Capture the CLI version, exact command, warnings, and PDF artifacts locally. For Rocky Mountain High, explicitly flag inconsistent declared key/capo/comment information for review; do not auto-rewrite it. A successful process exit alone does not prove anchors/tab/diagrams are correct: inspect the rendered pages.
- [ ] **Step 5 — Verify and commit.** Run package build/tests, bridge tests and Ruff. Record per-directive supported/preserved-only/error behavior and independent-renderer limitations in `chordpro-support.md`, referencing anonymous corpus IDs. Expected: no source loss; known anchors/tab match ground truth; unsupported constructs remain accessible and flagged. Commit `feat: add source-preserving ChordPro parsing boundary` with exact task paths.

## Task 3: Coordinate-based PDF draft conversion and honest fallbacks

**Files:** Create `server/songbook/imports/{models,pdf_extract,reading_order,convert}.py`, `tests/unit/test_pdf_conversion.py`, `tests/fixtures/synthetic/pdf_cases.py`, `tools/convert_corpus.py`, `docs/feasibility/conversion-results.md`.

**Interfaces:** `extract_pages(path: Path, pages: list[int]) -> list[PageExtraction]` includes character/word boxes, page dimensions and diagnostics; `render_page(path: Path, page: int, dpi: int) -> bytes` returns PNG. `convert_pages(pages: list[PageExtraction], regions: list[SongRegion]) -> list[ConversionDraft]`; `SongRegion` is song ID/label plus selected pages and optional normalized rectangles. Draft includes source hash/page/region references, generated ChordPro, uncertainty spans and diagnostics. These are drafts, never accepted arrangements.

- [ ] **Step 1 — Write conversion tests with coordinate ground truth.** `test_two_columns_read_down_then_across` uses interleaved PDF drawing order but asserts synthetic line IDs `L1,L2,R1,R2`. `test_chords_anchor_to_character_positions` checks exact inline positions across proportional glyph widths and adjacent chords. `test_vector_lyrics_are_not_declared_complete` uses a PDF with text chords and outlined lyric shapes, zero embedded images, and asserts `needs_visual_review` plus a renderable page. `test_tab_whitespace_and_graphical_fallback` preserves text string groups and attaches source refs for graphical notation. `test_song_ranges_span_pages_without_importing_whole_book` produces two selected drafts, including one spanning pages, and excludes unselected songs. Add ligatures/rotated text, corrupt/password-protected input, overlapping columns and content outside selected regions: unsupported results must be explicit diagnostics, not empty accepted songs.
- [ ] **Step 2 — Run failing tests.** `uv run pytest tests/unit/test_pdf_conversion.py -q`; inspect failures against synthetic expected text/anchors.
- [ ] **Step 3 — Implement bounded draft extraction.** Use char coordinates and detected gutters before row/chord pairing. Preserve uncertain items with page/box references instead of inventing lyrics or chords. Detect tab lines separately; retain page/crop references when text conversion is unreliable. Rasterize selected pages even when PDF image count is zero. Report low-confidence detection as review-required; visual completeness still needs human comparison. Enforce page count, image pixel, file size and subprocess time limits; start with configurable 100 MiB upload, 500-page registration, 20 pages per conversion job, 12-million pixels per rendered page and 120 seconds per local job. Larger sources may be registered but conversion requires smaller selections.
- [ ] **Step 4 — Measure the corpus.** Implement `uv run python tools/convert_corpus.py --manifest .local/corpus/manifest.json --output .local/evidence/conversion`. Compare every selected page with its draft, record missing/extra lines, wrong anchors, column order, tab loss and correction minutes. Keep known-bad cases in results. Prefer paired verified ChordPro to regenerating it from PDF; test that selection explicitly. Selection suggestions are review aids, never automatic title merges. Verify retained originals by hash.
- [ ] **Step 5 — Verify and commit.** Run conversion and existing unit tests plus Ruff. Expected: synthetic fidelity assertions pass; real samples have measured outcomes, accessible originals and explicit fallback/uncertainty status. Commit `feat: draft ChordPro from selected PDF regions`. If extraction candidates fail, keep the adapter contract and document the supported manual-review path before proceeding; do not assert successful automation.

## Task 4: Optional selected-page AI conversion boundary

**Interfaces:** `VisionProvider.convert(request: VisionRequest) -> VisionDraft` receives only explicit `SelectedPage` PNG bytes and page IDs plus instruction/schema; returns draft ChordPro, uncertainties, model, usage and request ID. `AIConversionService.convert(selection: PageSelection, authorization: ConversionAuthorization) -> ConversionDraft` validates server-owned selection, configured provider/model, page cap and explicit user action. `provider_status() -> ProviderStatus` exposes availability/model/limits/estimated-cost basis, never credentials. Authorization binds selected source/page hashes and provider/model; it is not reusable for other sources or pages.

- [ ] **Step 1 — Write provider-contract tests.** `test_disabled_without_configuration` makes no network call. `test_only_explicit_selected_pages_sent` captures HTTP payload and asserts two selected page images, no full PDF/unselected pages. `test_provider_failure_and_truncation_remain_drafts` covers timeout/429, malformed results, output-token exhaustion and uncertainty; none yields an accepted arrangement. `test_no_silent_paid_retry` asserts a timed-out submitted call is not automatically billed again. `test_secrets_and_lyrics_absent_from_logs` checks errors/status. `test_cost_is_unknown_without_rates` prevents an invented price; configuration with rates yields a labeled estimate, and returned usage yields actual usage-based cost where calculable.

- [ ] **Step 3 — Implement one adapter.** Follow current official Anthropic Messages/vision documentation using server-side `httpx`; model is required configuration. Send bounded selected PNGs, ask for ChordPro plus uncertainty/page mapping and prohibit invented missing content. Validate output via `parse_source`; retain provider errors for review. ## Task 5: Shared layout/PDF feasibility and final pipeline decision

**Interfaces:** `MusicBlocks({document, performance, mode}: {document: MusicDocument; performance: PerformanceSettings; mode:'play'|'print'})` renders data without executing source markup. M1 uses identity performance; M2 task 6 adds transformation. `render_pdf(request: PdfRenderRequest) -> PdfArtifact` consumes snapshots, performance settings, print settings and song-break mode; artifact includes immutable PDF path, SHA-256, actual page count, selected columns and diagnostics. Initial request uses one snapshot; M3 enables multiple. `PdfRenderRequest`/`PdfArtifact` are Python dataclasses mirrored in generated API schemas later.

- [ ] **Step 1 — Write browser/PDF feasibility assertions.** `feasibility.spec.ts` asserts music renders after sidebar mounting, chord anchors retain their lyric fragments at 390px, and tab uses `white-space: pre` without wrapping strings. `test_pdf_complete_at_selected_size` checks ordered synthetic section/line IDs including repeats, selected Letter/A4 media boxes, font size unchanged and embedded fonts. `test_oversized_sections_split_on_whole_lines` requires heading plus following line and no clipping; `test_wide_tab_reduces_columns_or_reports_infeasible` preserves complete string groups. - [ ] **Step 2 — Observe failures.** Run `npm exec playwright test tests/e2e/feasibility.spec.ts` and `uv run pytest tests/integration/test_pdf_feasibility.py -q`. Establish test app launch config and pinned browsers as needed; then confirm behavioral failures, not just missing executables.
- [ ] **Step 3 — Implement the smallest shared rendering path.** Bundle local fonts; wait for `document.fonts.ready` and a render-ready signal. Any impossible required fidelity is a real blocker to resolve, not a passing test. Optional AI unavailability is a documented limitation, not a blocker to manual review.
