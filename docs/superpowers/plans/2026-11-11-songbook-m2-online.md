# Useful Online Songbook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, inline. Steps use checkbox (`- [ ]`) syntax for tracking. No delegation is authorized by this plan.

**Goal:** Provide a private online library with durable reviewed imports, canonical editing, a dense responsive player and actual individual-song PDF preview/export.

**Architecture:** Build on M1's measured parser, converter and renderer. SQLite indexes managed canonical files and owns metadata/jobs; authenticated API routes serve the web application. Player and print components share the derived music model and performance transform without modifying canonical content.

**Tech Stack:** M1's locked dependencies plus FastAPI/Uvicorn, Pydantic, sqlite3/FTS5, Argon2 password hashing, React and Playwright. Generate frontend API types from server OpenAPI; use plain CSS and feature-scoped components.

**Spec:** `docs/superpowers/specs/2026-11-10-ukulele-songbook-design.md`; [master plan and contracts](2026-11-11-ukulele-songbook.md); prerequisite [M1](2026-11-11-songbook-m1-feasibility.md).

## Global Constraints

All master constraints/types apply. M1 report must record the selected parser/converter/paginator before this milestone. “ChordPro is the authoritative editable song format.” “An edit must not leave file content and its database index disagreeing after a crash.” “Do not overwrite canonical source chords when changing performance settings.” “The playing view hides persistent library navigation until requested.” “Print layout settings remain independent of play settings.” No deployment.

## Review Focus

1. Interrupted canonical write or failed disk rename: recover a consistent accepted revision before serving it (task 1).
2. Retried acceptance after a worker restart or later edit: no duplicates or overwritten user content (tasks 1 and 3).
3. Imported directives or source filenames act like HTML/path instructions: treat them as inert data and constrain roots (tasks 2–3).
4. Adjacent long chord names, narrow phones and oversized tab: no music loss, overlap or broken string groups (tasks 5–7).
5. A print change races with PDF completion: show the artifact for exactly the selected source revision/settings (task 7).
